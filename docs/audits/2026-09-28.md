## Spec-corpus audit (`specs-auditor`)

**2 findings**

### Duplicate

**1. The scheduled-audit mechanism is described twice, with identical details, in two specs — flagged for judgment
(candidate single-sourcing of the shared detail), not an automatic defect.**
`openspec/specs/showcase/quality/agent-skills/spec.md` ("The scheduled run SHALL perform the audits through the OpenCode
GitHub action's scheduled path — which requires a `prompt` input, authenticates by OIDC (`id-token: write`), and
produces a branch or pull request rather than an issue — and SHALL batch them into one run…") versus
`openspec/specs/showcase/quality/merge-governance/spec.md` (the workflow "SHALL invoke the audits unattended through the
OpenCode GitHub action's scheduled-run mechanism (a `prompt` input … and a single batched run…)", with
`id-token: write`, `contents: write`, and `pull-requests: write`). Both bodies state the same mechanism facts; the
behaviors are the same (one mechanism), but the two requirements live in genuinely different capabilities
(`agent-skills` owns which audits are schedulable and that `readme-auditor`/`experience-analyzer` stay on-demand;
`merge-governance` owns the CI workflow). The split is legitimate; the flag is only the duplicated mechanism detail.

**Suggested rewrite:** keep both requirements, but single-source the mechanism in `merge-governance` (the workflow
owner) and reduce `agent-skills` to a pointer ("…as specified in `showcase/quality/merge-governance` (Repository audits
run on a schedule and on demand)"), retaining only what `agent-skills` uniquely owns.

### Stale

**2. `merge-governance`'s Purpose enumerates the observational scheduled workflows and omits three workflow requirements
the spec now holds — ambiguous, may be deliberate.** `openspec/specs/showcase/quality/merge-governance/spec.md:7` —
"together with the observational scheduled workflows (the update checks, the upstream-reference report, and the
repository audits) that report without gating." The spec also holds "End-to-end tests run on a schedule and on demand",
"Dependency security scan runs on a schedule and on demand", and "A deployment smoke runs on a schedule and on demand" —
three more scheduled, non-gating workflows not named in the Purpose. The closing catch-all and the "that report"
qualifier can be read as deliberately scoping the parenthetical to _report_-producing workflows, so this is flagged as
ambiguous rather than asserted as a defect.

**Suggested rewrite:** either drop the "that report" qualifier and enumerate all scheduled workflows, or — if the
report/non-report split is the intent — add a sentence naming the test/scan/smoke trio.
