specs without archiving" run, contradicting the load-bearing "Sync the main spec only at archive" rule — a recurrence of
the 2026-10-04 advisory, still parked and still unapplied.** `openspec-sync-specs/SKILL.md:3` and the `opsx-sync`

sentence marking `/opsx-sync` as archive-internal. **Harm:** an agent or user following the generated command writes the

exact silent drift the archive-only rule exists to prevent. The legitimate use is inline within `openspec archive`.

run standalone (the fix is already parked at `docs/ideas.md:80-86`; it has not reached the rule's wording). Not an
upstream bug. The vendored `axon4to5-*` skills carry no new contradiction — the repo is on Axon 4 per ADR-0011 and the
skills are dormant migration tooling, not instructions the repo follows.

### Advisory

**1. ADR-0003's Jackson-3 deferral gate appears substantially met.**
`docs/adr/0003-retain-jackson-2-defer-jackson-3.md:7` — "Revisit when: the pinned `org.axonframework` and the
Elasticsearch Java client … resolve Jackson 3". The catalog now pins `elasticsearch-client-java = 9.5.4`
(`gradle/libs.versions.toml:34`) and `axon-framework = 4.13.2` (`:5`); the 2026-10-04 audit (recorded in

does Axon's Jackson-3 support being opt-in (not the default) mean the backend migration stays deferred behind Spring
Boot 4 (ADR-0004)?

**2. ADR-0011's Axon-5 deferral gate appears met on the framework axis.**
`docs/adr/0011-defer-axon-framework-5-migration.md:7` — "`org.axonframework:axon-bom` publishes a 5.x release and the
extensions and modules the project uses … ship 5.x, with a released (not preview) Spring Boot starter". Axon Framework
5.x is now GA — `5.3.3` released 2026-10-02, `5.4.0-RC1` in flight — and the renamed
`org.axonframework:axon-framework-bom` (5.2.x) plus the 5.x Spring Boot starter are published. The recorded premise that
the framework "has no 5.x" is expired; `config/dependency-updates/major-disabled.txt:4-5` ("the extensions/modules used
have no 5.x") and the `showcase/quality/dependency-management` spec's Axon requirement now state a fact reality has
overtaken. **Question:** confirm the Kafka and JGroups extensions' and the Micrometer/OpenTelemetry modules' 5.x status
against the coordinates, then re-plan the migration.
