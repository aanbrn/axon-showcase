### Findings

#### Structural

**1. The `## Conventions` "Docs refresh on change" bullet is one ~64-line bullet carrying ~10 independent obligations
and 9 `captured:` markers** — `AGENTS.md:1076-1139` (`- **Docs refresh on change**: on every change, verify whether …`).

- **Practical impact** — a reader must scan ~64 lines to reach the one obligation its change triggers (does this edit
  ride the change's PR or a separate docs PR? does the idea-removal ride the PR? is the config.yaml copy stale?). That
  density is precisely the class the guidance-evidence records document — several near-misses came from a docs-refresh
  obligation buried in this bullet.
- **Standard** — the Structured Writing Standard's "one independently actionable statement per unit" and "a paragraph
  MUST NOT carry several independently actionable statements, even when they share a topic" (`AGENTS.md:66-124`). The
  bullet holds these obligations as one continuous paragraph: verify the three live docs; the version-bump sweep;
  de-version examples; remove the idea in this PR; idea promotion is a link not a removal; the parked-entry status tag;
  sweep un-audited docs; update "the proposed X" prose; guidance-evidence records are live docs; the causation boundary;
  decide the owner before committing; the parked-idea refresh; the un-gated config.yaml/GitHub-description copies;
  removal counts too; SECURITY.md's private-reporting dependency.
- **Suggested rewrite (minimal, preserves every `captured:` marker and anchor)** — keep the bold-lead as the entry point
  and split the body into labeled sub-bullets, one obligation family each, so each is scannable and greppable:

```
- **Docs refresh on change**: on every change, verify whether `AGENTS.md`, `README.md`, and `docs/adr/` need to be
  refreshed to reflect the new state (commands, config, conventions, gotchas) — including an ADR whose Consequences name
  a follow-on this change lands, or whose Decision it alters. The sub-rules below name each sweep's trigger.
  - **Version bump** — a dependency/tool/wrapper bump stales every live doc naming the bumped version; grep the old
    string across the working tree (untracked artifacts included) and fix each live mention, since no gate reads them;
    de-version an illustrative example rather than re-versioning it. captured: bump-dependencies-2026-10-12
    captured: bump-dependencies-2026-10-25
  - **The change's own idea** — remove it from `docs/ideas.md` in this PR, not a separate docs PR; promotion to a GitHub
    issue is a link (annotate, never delete); give every parked entry a trailing status tag. …
  - **Sweep the un-audited docs** — `docs/ideas.md` and retrospective suggestion rows, marking each suggestion's
    disposition rather than removing it; an open idea still calling it "the proposed X" is itself stale. …
  - **The guidance-evidence records are live docs too** — refresh a falsified upstream status/supersession/retirement in
    the change. captured: address-scan-findings-2026-10-25
  - **Causation boundary while the change is in flight** — docs that ARE the change and edits the change causes ride its
    PR; edits it did not cause and edits surfaced after it ships as their own batched docs PR, forked from `main`;
    decide the owner before committing. …
  - **The un-gated copies** — `openspec/config.yaml`'s `context:` block and per-artifact `rules`, and the GitHub
    description/topics: sweep them when a rule moves, including a removal; no auditor owns a surface outside the repo. …
  - **A file that depends on an external surface** — `SECURITY.md`'s private-reporting path needs the repository setting
    enabled in the same change, and the enabling named in the change's report. captured: park-retro-marking-idea (#281)
    captured: re-measure-load-test-baseline (#429) captured: mark-s3-applied captured: attribute-load-test-tail (#570)
    captured: park-review-loop-follow-ups captured: fix-openspec-config-rules
```

(This is a reorder-and-split only; the nine `captured:` markers stay attached to their clauses, and no warning,
imperative, or identifier is dropped. This is a `structural` rewrite, not a merge/removal/route — the content stays at
root because it is a repository-wide workflow rule that fires on every change.)
