### Advisory

**1. ADR-0011's `Revisit when:` Kafka clause names an open-source coordinate that appears to be overtaken by a
commercial move.** Anchor: `docs/adr/0011-defer-axon-framework-5-migration.md:7-13`; `gradle/libs.versions.toml:6`
(`axon-kafka = "4.12.1"`). Evidence: the open-source `org.axonframework.extensions.kafka:axon-kafka` remains at 4.12.1
(no 5.x), while AxonIQ's 5.4 framework-comparison table marks "Event publishing and handling — Kafka integration" as
absent (`X`) from open-source Axon Framework 5 and present in Axoniq Framework (commercial) at `5.5.0`, and
`AxonIQ/axoniq-framework` PR #642 "Add a Kafka connector" targets release 5.5.0. Classification: externally checkable
conjunction; the Kafka clause is not met, and — unlike the ADR's 2026-10-12 re-check, which said the extension was
"still unmigrated and on the roadmap" — the premise is now in question, because Kafka integration appears to be landing
in AxonIQ's commercial framework (the same move the gate already records for the JGroups clause), not in the open-source
coordinate the gate names. This is the frozen-coordinate class the repository already corrected once (`axon-bom` →
`axon-framework-bom`, `correct-adr-0011-axon5-gate`). Question whose answer records the corrected intent: should the
Kafka clause be restated to name AxonIQ's commercial Kafka connector and fold into the existing
commercial-versus-open-source routing clause, since the open-source coordinate it names may never publish 5.x?

**2. ADR-0017's `Revisit when:` names a "maintained first-party Spring gRPC line targeting Boot 3.x" that can no longer
materialize.** Anchor: `docs/adr/0017-grpc-query-transport.md:7-12`. Evidence: Spring gRPC's maintained lines are
1.0.3/1.1.1 (targeting Spring Boot 4.x / Spring Framework 7); first-party gRPC starters
(`spring-boot-starter-grpc-server`) shipped in Spring Boot 4.1, not any 3.x line; and Spring Boot 3.5 OSS support ended
2026-06-30. Classification: externally checkable; the condition is not met, and its premise has expired — a maintained
Boot-3 line can no longer appear, so the gate as written (even after its 2026-10-19 "maintained, not any" correction,
`correct-adr-0017-spring-grpc-gate`) names a condition that can never fire. Question whose answer records the corrected
intent: should ADR-0017's `Revisit when:` be restated to key on ADR-0004 (the Boot 4 migration, which now also delivers
first-party gRPC in Boot 4.1) instead of on a Boot-3 Spring gRPC line?
