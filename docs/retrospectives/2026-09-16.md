# Retrospective — 2026-08-11 → 2026-09-16

The project's first retrospective, over the whole OpenSpec/agentic era: the window opens at the first archived change
(2026-08-11; the first merged PR, #1, followed on 2026-08-27), so it covers all 252 merges. Gathered with
`scripts/experience-analysis.sh 2026-08-11`. Figures below were verified against the repository, not taken from the
digest's prose.

## Shipped work, by phase

**Phase 0 — spec capture and build hygiene (archived Aug 11–25, pre-PR-gate, direct commits).** 86 changes were archived
before the first merge — 11 of them `capture-*` behavior captures, alongside the role-group restructure, the test-tier
and display-name conventions, the coverage gate, Checkstyle/Spotless/ErrorProne, the first ADRs, and the first
`AGENTS.md` conventions. Everything since assumes this corpus and these gates.

**Phase 1 — CI, merge governance, infra single-sourcing (#1–#42).** The `merge-governance` ruleset and CI gate, the

**Phase 2 — web UI and the first gates (#43–#95).** `add-web-ui` (FSD, gateway SSE, CORS) and its Playwright e2e suite,
npm/Node CI caching, ESLint 10, the root markdown Prettier gate and ktfmt for build-logic, actionlint, the deployable

**Phase 3 — agent-tooling build-out (#96–#199).** `lesson-capture` (#96), `experience-analyzer` (#98), `review-thorough`

**Phase 4 — hardening, audits, and the meta tail (#200–#256).** `.opencode/` under Spotless (#203), the OpenSpec
config-rules guard (#218), the `showcaseCache` default (#220), the shared report contract (#231) and the
commit-only-when-forced discipline (#236), a chart bump (#238) — then a tail of captures, ending in #254→#255→#256: a
script fix plus the two captures it generated.

## The finding

**Meta-work outran product work, and the capture loop is what drove `AGENTS.md`'s growth.**

- **121 of 252 merged PR titles** begin `Capture|Park|Note|Document|Record|Archive|Refresh`.
- **#200–#256 contains two product changes** — `#220` (the `showcaseCache` default) and `#238` (the KPS chart bump).
  Every other merge in that range touches the agent tooling, the spec corpus, or the docs about them.
- **`AGENTS.md` reached 1534 lines / 21,386 words / 101 bullets** (48 of them in `## Gotchas`) in five weeks, with the
  capture-after-every-merge rule as its growth engine; the `agents-auditor` prunes only on demand.

Cost follows from the same place: review-round count dominates, not the hour a pass runs. The tail's three-PR capture
chain — where each round's review caught the author's own errors in the prose _about_ the process — cost far more than
the 2× peak-tier premium that motivated the off-peak idea.

## Went well

- **The review gate caught every process error before it reached `main`** — none shipped. Notably, none was caught by a
  gate either: every one was prose, and no gate reads prose.
- **The auditors found real, previously invisible drift**: the unrecorded Axon-Server and Axon-4.x-pin rationale, the
  `query-api` re-export, stale spec headers after the role-group restructure.
- **Single-sourcing plus a verification task converted prose into gates** — infra image versions, the version catalog,
  `buildpackUpdates`.
- **Asking recovered what writing down would have lost**: ADR-0009's missing rationale came from the owner, not from a
  guess recorded as "unrecorded".
- **The branch/commit discipline removed a failure mode by construction** (the 11-commits-per-change pattern).

## Went wrong

- **Every one of the owner's premise questions found something the agent's own review had not asked** — whether the
  release-name-dependent pod labels still made sense, why a change showed no touched files, whether an agent-only script
  belonged in `scripts/`.
- **Four consecutive capture rounds**, three of them captures of captures, to land a handful of one-line doc fixes; the
  chain terminated only when the arbiter said "nothing durable".
- **Written rules did not enforce themselves**: a capture was applied directly on `main`'s working tree, violating a
  rule that cites the identical earlier incident. The rule existed and was still missed.
- **A verification whose output was not read** (a 120-character check printed the offending line, then an unconditional
  "clean" echo contradicted it), and then the same check left **vacuous by a bogus filter** — the second error was a
  repeat of a class already recorded.

## Improvement suggestions

Classified `process` (→ `AGENTS.md` or a subagent definition) or `system` (→ `docs/ideas.md` / an OpenSpec proposal),
with the disposition taken in the change that added this document.

| #   | Suggestion                                                                                                                            | Class     | Disposition                                    |
| --- | ------------------------------------------------------------------------------------------------------------------------------------- | --------- | ---------------------------------------------- |
| 1   | Consolidate the verification-vacuity cluster — five bullets share one root: a check is evidence only once it has been shown to fail   | `process` | **Applied** (net-reductive)                    |
| 2   | Make `lesson-capture` consolidate rather than accrete: every proposed rule names the bullet it extends, or states that none covers it | `process` | Own change — alters a spec'd subagent contract |
| 3   | Fold a lesson discovered while writing a capture into that capture's PR                                                               | `process` | Parked in `docs/ideas.md`                      |
| 4   | Merge the parked scheduling/cost ideas into one scheduled unattended-run workflow                                                     | `system`  | Parked in `docs/ideas.md`                      |
| 5   | State once where agent-only tooling lives (`scripts/` for repo tooling, `.opencode/` for runtime config, agents, commands, skills)    | `process` | Parked in `docs/ideas.md`                      |
| 6   | Pre-commit guard over the staged set (format-after-final-write, staged build artifacts, paths staged-then-edited)                     | `system`  | Parked in `docs/ideas.md`                      |
| 7   | Make the next phase a product phase — the tooling is mature enough to be used rather than extended                                    | `system`  | Recorded below and in `docs/ideas.md`          |

The analyzer's own caution applies: suggestions 2, 3 and 5 touch `AGENTS.md`, which is the growth pattern itself — so
only 1 (net-reductive) is taken here, 2 is taken as its own change, and the rest wait.

## Recommended next direction

Use the tooling rather than extend it. The highest-value parked candidates are the ArchUnit fitness functions (the
architecture has decide/describe/review layers but no _enforce_ one), narrowing the `query-api` re-export, and web-UI
trace propagation. Every further rule added to `AGENTS.md` is a future drift surface; the next change should be one a
user can see.
