# Retrospective — 2026-09-16 → 2026-09-19

The window's second retrospective, covering 56 merged PRs and 18 archived changes from a single long session — the
densest window the project has had. Gathered with `scripts/experience-analysis.sh 2026-09-16`. The figures below were
re-derived from the repository (`git log --numstat`, `wc`), not taken from the digest's prose.

## Shipped work, by theme

**1. The capture loop turned on itself (the window's highest-leverage work).** `reshape-the-capture-loop` (#289)
replaced the after-every-merge capture with a merge-time _detection_; `sharpen-the-capture` (#293) made it one capture
per unit, added the decision test (a rule that governs no decision is not proposed), and gave `review-quick` a
capture-worth check; `widen-auditor-to-merge-and-removal` (#294) and `refine-the-merge-analysis` (#296) made merge and
removal candidates standing `agents-auditor` findings. Around them, the capture/consolidation/parking PRs did the actual
accretion and pruning. Net: the _engines_ that grow `AGENTS.md` were bounded for the first time — no chaining, a
decision filter, and a consolidation obligation inside `lesson-capture`.

**2. Two real gates and one product behavior.** `enforce-module-dependency-graph` (#269) gave the architecture its
missing _enforce_ layer; `unify-tooling-currency-checks` (#304) added the `toolingUpdates` check and workflow, closing
the last un-monitored tool pin; #306 tested the `build-logic` rule sets and unified three disagreeing version
comparators into `Versions`; `keep-sse-stream-alive` (#301) fixed a deployed-only bug (an idle SSE stream carried no
bytes).

**3. Auditors: the fourth shipped, and the set was consolidated.** `add-readme-auditor` (#315) added the
`readme-auditor`/`/audit-readme` pair on a distinct artifact and audience (humans), with its smoke-run finding three
real pre-existing README defects; `consolidate-agents-audit-findings` (#313) applied the first full `agents-auditor`
pass's reconciliation items; `reconcile-readme-agents-architecture` (#317) retired a disproved idea.

**4. Repository representation and docs truth.** `improve-the-repository's-outward-facing-representation` (#266), the
architecture service-count reconciliation (#278), `gate-github-markdown-with-prettier` (#311), and the Snyk pin bump
(#309) — which the new check had detected on its first real run (#308).

## The finding

**The capture loop's shape was fixed; its output still outruns the prune by roughly an order of magnitude.**

- `AGENTS.md` moved from 1,559 to 1,835 lines in three days (re-derived: `git show 7d4bb0f:AGENTS.md | wc -l` = 1,559;
  `wc -l AGENTS.md` = 1,835, **+276 net**), across the 40 commits touching the file in that range
  (`git log 7d4bb0f..HEAD -- AGENTS.md`, all non-merge since the repo squashes). Top-level bullets now 148.
- The capture PRs are net-positive and large; the consolidation PRs are net-negative but small — roughly **−16 net
  across six consolidation PRs against roughly +220 net across seventeen captures**.
- The two meta changes that were _net-neutral or net-reductive_ shipped a **mechanism** (#289/#293 reshaping the
  trigger, #313 applying an audit), not prose. The standing merge/removal analyses exist in the auditor but ran only
  when a human asked.

So the counterweight is finally present in _kind_ — merge and removal candidates are standing findings — but not in
_frequency_. The remaining question is purely a trigger: what makes the consolidation pass fire without a human.

## Lessons carried through this window

- **A check is evidence only once it has been shown to fail.** The window's instances — a digit-truncating module-name
  regex reporting a false absence (traceable: the README↔AGENTS reconciliation, recorded in the `AGENTS.md`
  check-evidence bullet), plus two scratch-command false signals the session hit but which left no repository trace (a
  `/tmp/` write misread as a no-op and an unopened `pbcopy` pipe) — all fall under modes the bullet already holds. The
  seven sub-modes each carry distinct anchors, so the block is owed no content merge; its lead's hard count is the one
  drift surface (suggestion 1).
- **The `captured:` marker rule is clear but mechanically violated.** The mid-bullet-vs-bullet-end slip recurred (one
  instance is recorded — `AGENTS.md`'s provenance gotcha — and the 2026-09-19 window hit it in several captures as the
  session's account), each time from a script deriving item boundaries wrongly, not an ambiguity in the rule. What is
  missing is a check (suggestion 2).
- **The auditor-justification rule held.** `readme-auditor` was correctly separate for a distinct artifact and audience
  with a gate-free content surface; `agents-auditor` was not widened. But the change's _planning_ proposed widening
  `agents-auditor` past the parked `readme-auditor` idea, and the owner caught it — the premise-interrogation bullet now
  carries that incident, but the catch came from a human, not a gate.
- **A smoke-run is verified in two dimensions.** `readme-auditor`'s run proved both: a seeded accuracy control (found)
  and the exclusion of a deliberate asymmetry (excluded), plus three real defects beyond the seed. The `agents-auditor`
  re-run as its own control caught the regression the structural fix introduced (#313 task 5.4).

## Went well

- **The capture trigger was fixed by construction, not by another rule.** #289 replaced a chain-prone trigger; #293
  added the decision filter; #313's consolidation did not chain. No four-round capture chain appeared.
- **Positive controls were used for real.** #311 proved the widened markdown gate fires by appending a long line; #304
  proved the tooling check both ways; the review caught that the GitHub parse only matched pretty-printed JSON, which
  would have left two checks intermittently vacuous.
- **The audit→apply→re-run loop caught its own regression** — the `agents-auditor` re-run found the `###` promotion's
  unclosed list scoping ~40 later gotchas.
- **The new check closed its loop within the window**: `toolingUpdates` detected the stale Snyk pin on its first real
  run, opened #308, and #309 fixed it.
- **The fourth-auditor smoke-run paid for itself immediately** (three real README defects, all fixed in the introducing
  change).

## Went wrong

- **Net accretion outran consolidation ~10:1** (the finding). The auditor's merge/removal analyses are on-demand only.
- **The same false-signal class recurred**, with the traceable instance (the digit-truncating regex) plus the session's
  account of two scratch-command false signals (the `/tmp/` write and the `pbcopy` pipe, neither leaving a repository
  trace), all in the agent's _own scratch checks_ during implementation, none in a repo gate. The prose that guards it
  is in `AGENTS.md`; it did not fire at the moment of the scratch command.
- **The `captured:` placement slip recurred**, each time caught by review rather than by a check.
- **Two structural attempts were made and reverted** (the check-bullet `###` promotion; earlier the chart-default redis
  label). "Reorganize this block" has now been tried and does not hold.
- **A verification that can only run post-merge was left only in the archive.** #311 deferred the GitHub
  template-rendering check and recorded it as an unchecked task inside `openspec/changes/archive/` — invisible to every
  gate.

## Recommended next direction

The first retrospective said "use the tooling rather than extend it"; this window mostly extended the _process_ tooling
again, but for the first time it also made that tooling shrink its own growth rate. The highest-value work now is to let
the mechanism run: decide the consolidation trigger (suggestion 3) and add the one mechanical marker check (suggestion
2), then return to product work — the highest-value parked candidates remain narrowing the `query-api` re-export and
web-UI trace propagation.
