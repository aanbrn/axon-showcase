## The central finding

**The review loop's cost is now the window's dominant process cost, and its root cause is derivation rules that already
existed but were not applied on small, familiar units.** The kube-prometheus-stack chart bump (#558) took **8 rounds on
a 2-line diff**; ADR-0011 (#553) three proposal plus three implementation rounds; the dependency bump (#555) and the
Snyk pin (#557) three each — the chart bump's count is recorded in its archived `tasks.md`, while the others are the
session's own counts and are not, which is the gap S3 exists to close. Several rounds' findings were **compliance misses
of rules already in `AGENTS.md`** — so the loop re-derived, one finding at a time, what a pre-write derivation pass
exists to derive at authoring time. That _pass_ is new: it landed (#550) _inside_ this window, so it could only govern
units branched after its merge and did not prevent the same window's rounds — the _rules_ it applies pre-dated it.

Two structural facts sharpen it:

- **A rule can be present, cited, and still not applied.** #555's capture added "a version bump greps every live doc
  that names the bumped version"; #556 — the next unit, the same day — moved the two buildpack pins `AGENTS.md` names
  and did not grep for them, even though its branch's parent _was_ #555's merge and its own `tasks.md` cites the clause.
  The miss was an **application failure**, not an absent rule — the same class the headline names, not a separate
  structural one. (Branch isolation is real but was observed elsewhere: the Snyk branch was cut while #556 was unmerged,
  so its `AGENTS.md` read pre-change until `gh pr update-branch` merged `main` back in.)
- **The reduction engine engaged once, and accretion still outpaced it.** One net-negative `AGENTS.md` commit (#540, −3)
  and three applied reduction candidates, against a window that grew the file: 2,693 → **2,965 lines** (+272), 172
  top-level bullets (+8), 162 lines carrying a `captured:` marker (+41), and 47 of the 54 PRs touching `AGENTS.md` — of
  which eight `captured:` markers name this session's own changes (`cut-review-loop-rounds`,
  `record-worktree-cost-measurement`, `correct-adr-0011-axon5-gate`, `record-remaining-architecture-advisories`, and the
  four 2026-10-12 bump units), carrying eleven rule clauses between them. Derive the set by grepping `captured:` against
  the session's change names rather than listing it from memory: this list alone cost three review rounds.

Also worth recording:

- **A review correction deleted a true statement.** In #554 a true claim (a POM's `co.elastic.clients:*` exclusion) was
  _removed_ because the check searched Maven's `<exclusion>` using Gradle's `<exclude>`; the next round caught it and
  the claim was restored after re-verifying with a positive control. "A correction that deletes a statement has no
  downstream reader" is now in `AGENTS.md`.
- **A diagnostic leaked credentials.** `./gradlew --info` dumps each exec'd process's full environment into captured
  output; no artifact quoted the values, but the rule is captured and the upstream note parked.
- **An approval request outlived its unit.** A merge request went unanswered while the reply moved the thread to the
  next unit, so the earlier PR sat unmerged and the next unit's branch, cut from `main` while it was unmerged, read
  pre-change — looking like a revert.

**S1 — make the pre-write derivation pass a visible, per-unit checklist task.** **Applied** in
`make-the-pre-write-pass-visible`: the pass is a `tasks` rule and a PR-checklist line, and the review-loop bullet
carries its record. The original proposal: the window shows prose in `AGENTS.md` is skipped on small, familiar units.
The repo already has the working pattern: `make-the-capture-visible` made the capture a ticked task, so a skip is a
_missing box_. Mirror it — require a named planning task in every change's `tasks.md` (and a PR-checklist line for a
unit with no change dir) recording that the pass ran and naming its four claim classes.

**S2 — extend the documented-pin verification to every pin a live doc names.** `verifyInstallCommands` already asserts
the manual `helm install … --version` commands against the catalog chart pins. The buildpack pins `AGENTS.md` names are
the mechanically checkable subset of the version-bump grep, and they are exactly what #556 missed. Widen the check (or
add a sibling) to cover the pins live docs name — deriving that set by grepping the five live docs for version strings
rather than listing it from intent, since a hand-written list under-describes what the grep returns. Each is asserted to
match exactly once.

**S3 — record per-unit review rounds and their causes.** The window's dominant cost is unmeasured, so #550's pre-write
pass cannot be evaluated next window. Park a mechanism for `review-quick` (or the retrospective digest) to report each
round's findings by class and whether each was a compliance miss of an existing rule.

## Recommended next direction

The audit loop is self-reducing and the merge hazards have mechanical nets, so the loop's tooling is close to done. The
window's strongest signal is that the loop's cost is now dominated by rules not being applied — and the response so far,
more prose in `AGENTS.md`, lengthens the file and further buries the rules. The next window's highest-value work is to
convert the top recurring rules into mechanisms (S1, S2), then _use_ the mature tooling: the product-phase direction has
now survived four windows and shipped one user-facing artifact.
