- **A mechanism landed against the window's top class.** `claim-scan.py --verify` executes a claims row's command at the

  pointer from `review-gate` §1, the parked idea removed. Its pilot bounded its value honestly: 6 of 44 historical rows
  checkable, 0 mismatches after the deep review's comparison fix.
- **A negative probe produced a durable verdict instead of prose.** The edit-path pilot measured the v2 plugin surface
  (`opencode v2.2.3`: no tool, permission, or session hook; six static `*.transform` drafts; `aisdk` wrappers only),
  named its stop condition, and redirected the work to the claims mode rather than shipping another reminder.
- **The routing floor fired where it mattered.** `add-claims-execution-verify`'s deep-review outcome was `RECOMMENDED`
  on `[repeated-class]` (11 rows repeating a class); the owner ran the pass and it found six issues the 16-round quick
  loop had not. The escalation was explainable and reproducible rather than a judgment.
- **The guard family closed the "act done, not recorded" class.** Four dirs archived on 2026-10-24…26 carry seven
  unticked boxes; after `guard-archived-task-boxes` (#739) landed, the dirs archived to 2026-10-31 carry none — by
  construction (a strict guard forces a tick or a rewrite), but the first window in which no dir archived after the
  guard carries one.
- **The generalization pass was cheap and honest.** 66 undecided records → one proposal applied (a +2-line clause in the
  `gradle-build` pack), 65 `no-change`, five quick rounds. The owner challenged the minimal output; the follow-up units
  were chosen to produce a mechanism, which is how the probe and the claims mode came to exist.

## Improvement suggestions

**S1 — `process`: park until a concrete uncovered authoring decision is recorded.**

- **Pattern**: `AGENTS.md` grew +174 lines while the pause held, and the growth is new procedure at root; but the
  placement principles exist (`agent-skills` 350–387; `lesson-capture` 37–44) and lesson authoring already selects an
  owning destination. Section-size changes establish growth, not that all growth was misplaced procedure; root
  invariants must stay visible, so a near-zero section delta is not sufficient evidence of improvement.
- **Expected outcome / verification**: a concrete authoring decision that no existing rule covers; verify by
  demonstrating timely retrieval and preserved obligations, not merely near-zero root growth.
- **Where**: park; revisit with that decision.

**S2 — `process`: apply narrowly — prefer an explicit-literal Result where the complete assertion and supported command
fit the mode.**

**Applied in `prefer-claims-literal-results`.**

- **Pattern**: `review-gate` §1 permits execution conditionally but states no authoring preference;
  `claim-unreproducible` is the most-raised class. The coverage forecast is unestablished: the skips also reflect
  two-column tables, unsupported commands, ambiguous pipes and working-tree measurements, so literal formatting fixes
  only part of the denominator.
- **Expected outcome**: a row whose complete assertion and supported command fit the mode states the literal or literal
  list; explanations stay outside that cell; evidence is never weakened to obtain a checked row.
- **Verification**: the next window's checked/skipped counts by skip reason, and whether the literals represent the full
  claim — a higher checked fraction alone does not demonstrate fewer unreproducible claims.
- **Where**: `.opencode/skills/review-gate/SKILL.md` §1, beside the `captured:` bullet; the `agent-skills` delta if the
  fields are spec'd.

**S3 — dropped.** A named task already existed (task 2.1 named D2–D7), and one numbered decision can contain several
independently testable clauses; the numbered decisions also include scope and `skip_specs`. A design-to-test reread
would also need reconciling with "No semantic self-review precedes the loop". An authoring-time behavioral coverage
model is a different proposal; this one does not discriminate the motivating failure.

**S4 — dropped.** The 2026-10-23 report initially said "parked"; #739's task 4.4 updated it to "Applied" (the archived
`2026-10-29-guard-archived-task-boxes/tasks.md:48–49`), and #739's deep pass R1 fixed the reports still calling it
parked. The proposed date rule would also reject legitimate later updates to earlier retrospectives.

**Not proposed:**

- **Raising the `repeated-class` routing signal from `RECOMMENDED` to `REQUIRED`.** The one instance (11 repeated rows →
  the owner ran the pass → six findings) shows the mechanism worked, not that it should be stronger; the floor's
  advisory design is deliberate and the owner's resolution is part of it. Revisit if a unit with a high repeat count
  ships without the deep pass.
- **A per-consultation record** (the previous report's P3). Three consultations found something material, but the owner
  selects when to consult, so the hit rate is not a rate; a field, a delta, and its upkeep are not yet justified.
- **A rule for the `Decision:` line's vocabulary.** Eleven records say `proposed: applied as …` and none says `shipped`,
  so the state cannot be read without checking the merge — but the line still ends the analysis, so the cost is a
  reader's, not the loop's. Record it if a pass is ever confused by it.
