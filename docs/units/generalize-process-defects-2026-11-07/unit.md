### P1 — AGENTS.md, a bold-led bullet in the subject-pack section

Add one bullet after the section's "Load every pack whose row matches the task" bullet, so the caller checks a change's
planned or actual edited paths for a subject its decisions did not name. Exact text:

> - **Check a change's planned or actual edited paths for a subject the decisions did not name, before its first
>   governed decision.** Paths are evidence for the table's decision triggers, not triggers by themselves: an edit to a
>   build script, convention plugin, or version catalog often carries a `gradle-build` decision, while a formatter-only
>   change to one carries none. captured: assert-paketo-pin-coverage captured:
>   guard-recreate-strategy-across-deployments captured: reject-ignored-openspec-delta-sections captured:
>   surface-projector-backlog captured: unit-layout-allowlist

It extends the existing sentence "classify by what the change will decide, not by whether it touches a file yet" — the
caller-side counterpart of the reviewer bullet's "changed paths as evidence rather than the only predicate". The
qualifier keeps the routine-verification exception: a formatter-only edit of a build script loads no pack. Each record's
own field states what the hand-over carried:

| ---------------------------------------------- | ---------------------------------------------------------------------------------- |
| `assert-paketo-pin-coverage#5`                 | "the hand-over for round 9 named no pack"                                          |
| `guard-recreate-strategy-across-deployments#1` | the hand-over's `Packs: deployment-operations` line                                |
| `reject-ignored-openspec-delta-sections#2`     | "every hand-over from round 1 to round 7 declared `Packs: none`"                   |
| `surface-projector-backlog#2`                  | "the hand-over named no pack owning the build file"; the line itself is not quoted |
| `unit-layout-allowlist#1`                      | "stated `Packs: none` and excluded the four rows"                                  |

Every one of the five left `gradle-build` unnamed, while three of them carried a `Packs:` statement — so the field's
presence is not the missing piece, and the classification that produced it is the site.

The bullet carries one actionable statement and its examples, so it belongs in the section's bullet list rather than in
the definition paragraph; leaving that paragraph unchanged keeps the change to the increment.
