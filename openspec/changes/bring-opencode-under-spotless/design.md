## Context

The root Spotless markdown target (`build.gradle.kts`) covers `docs/`, `AGENTS.md`, `README.md`, `openspec/specs/`, and
active `openspec/changes/*/` — a scope recorded in four places this change refreshes together: the
`showcase/quality/code-quality` spec, AGENTS.md's **Line Length** bullet and `Formatting` convention, and README's
`Formatting` section. `.opencode/` sits outside it.

`.opencode/` is a mixed tree:

- **Project-authored** — 9 agent definitions, 13 commands (the 12 non-`opsx-*` ones plus the project-authored
  `opsx-tool-update.md`, which shares the generated prefix), and 2 skills (`setup-agent-tools`, `setup-idea`): 24
  markdown files in scope, of which 23 currently need reformatting.
- **Generated by `openspec update`** — 6 `opsx-*` commands and the `openspec-*` skills.
- **Vendored** — the three `axon4to5-*` skills, which AGENTS.md requires be copied verbatim from upstream.
- **Project-owned config** — `.opencode/opencode.json`.
- **`node_modules/`** — gitignored but present on disk.

Its current checks are hand-rolled line-length instructions written into the two audit commands and the `review-quick`
and `review-thorough` agents — checks that have already failed silently once (PR #199 fixed a `.opencode/*.md` glob that
matched no file).

The churn was measured with the real config in a throwaway experiment before this change was written: 23
project-authored markdown files, 132 insertions / 115 deletions, purely rewrapping plus Prettier's frontmatter style,
missing trailing newlines, and its `_emphasis_` normalization; `spotlessCheck` passes afterwards. (The final diff is
larger, because tasks 3.1–3.6 add content edits on top of that reformatting.)

## Goals / Non-Goals

**Goals:**

- The project-authored `.opencode/` markdown and the config JSON are covered by the same Prettier gate as the rest of
  the markdown, verified in `check`.
- The generated and vendored files stay byte-identical.
- The manual line-length checks the gate supersedes are deleted or re-scoped rather than kept alongside it.

**Non-Goals:**

- Formatting the generated or vendored files (they are not ours to reformat).
- Introducing a `.prettierignore` or a second formatter — the target scope is the tool the repo already uses.
- Reformatting anything else under `.opencode/` (there is no other project-authored source there).

## Decisions

### A scoped target with explicit exclusions, not `.opencode/**/*.md`

A recursive glob also matches `node_modules/`, the generated `opsx-*`/`openspec-*` files, and the vendored `axon4to5-*`
skills — all of which carry >120-character lines, so a "clean" check over that glob would be unachievable (this is
exactly the over-match a `review-quick` pass caught in PR #199). A positive per-file list would be brittle. The target
therefore names the project-authored directories and excludes the rest.

### The generated `opsx-*` commands are excluded by name, not by prefix

`opsx-tool-update.md` is project-authored and must stay in scope, so an `opsx-*` prefix exclusion would wrongly drop it.
The six generated command names are listed explicitly. Their regeneration path — `/opsx-tool-update`, which already
re-syncs the instruction files after an OpenSpec release — is extended to check the exclusion list still matches what
the generator wrote, so a future `opsx-*` command does not silently get reformatted and then overwritten.

_Alternative considered_: exclude the whole `opsx-*` prefix and accept that the one project-authored file is not
formatted. Rejected — it abandons the file that most needs it (it is prose the repo maintains by hand).

### The config JSON is formatted by a block with its own config

A `format` block's `prettier` applies only to the paths that block targets, and the JSON needs different options from
the markdown, so it gets its own block, pinned to `printWidth: 120` (Prettier's default is 80, which would explode the
`command` array one element per line). It is scoped to `.opencode/opencode.json` specifically rather than
`.opencode/**/*.json`: a future vendored skill shipping JSON must not be reformatted (the same byte-identity rule that
excludes the vendored markdown).

### The frontmatter restyle is verified, not assumed

Prettier rewrites an agent's frontmatter from `description: <first line>` to `description:` followed by an indented
block. That is valid YAML and semantically identical, and folded multi-line descriptions already exist in the repo — but
the consumer is the agent loader, so the change verifies each reformatted file's frontmatter parses to the same values,
and smoke-tests a subagent after an OpenCode reload rather than assuming the loader is indifferent.

### The superseded manual checks are removed or re-scoped

Keeping a manual command alongside a gate that now performs the same check is the redundancy the repo's own convention
warns against (a second copy that drifts) — and a hand-rolled line-length check can also false-flag a backtick-dense
line that Prettier legitimately leaves over 120. The instances are swept, not fixed one at a time: the two audit
commands' `.opencode/` instruction is deleted and their step-4 "formatter-wrapped files" enumeration gains the
`.opencode/` files they edit; the two review agents' line-length instructions — `review-quick`'s 120-character run and
`review-thorough`'s "120-column" convention item — are re-scoped to the changed files the formatter does not cover (e.g.
YAML), since everything else they check is now gated; and `/ideas`'s "wrap within 120 characters" hint for the
formatter-wrapped `docs/ideas.md` is dropped. The _general_ gotcha — "a glob written into an instruction file is
unchecked; prove it matches" — stays, because it is about any glob, not about `.opencode/`.

## Risks / Trade-offs

- **[A future OpenSpec release adds a generated `opsx-*` command]** → it would be reformatted, then overwritten by
  `openspec update`, producing churn; mitigated by the `/opsx-tool-update` exclusion-list check.
- **[The frontmatter restyle breaks an agent's load]** → mitigated by the parse-equivalence check plus a subagent
  smoke-run after a reload (the change does not archive while that is unchecked).
- **[The one-time 23-file reformat inflates the diff]** → it is mechanical and `spotlessCheck`-verified; isolating it in
  this change keeps later diffs clean.
- **[A vendored file is reformatted]** → the exclusions were verified against the real formatter (the vendored and
  generated files were untouched); the vendoring convention's byte-identity is preserved.
